# FitConnect AI Memory Bootstrap

**Status:** ENFORCED companion to `.ai.constitution.md`

Every AI/developer session that changes FitConnect MUST read, in order:

1. `.ai.constitution.md`
2. `.ai.memory.md`
3. `docs/ai-library/CURRENT_STATE.md`
4. `docs/ai-library/ARCHITECTURE_INDEX.md`
5. `docs/ai-library/OWNERSHIP_REGISTRY.md`
6. `docs/ai-library/SECURITY_BASELINE.md`
7. relevant domain file(s) under `docs/ai-library/domains/`
8. relevant incident records under `docs/ai-library/incidents/`
9. current Git/Supabase production state before mutation

## Memory hierarchy

- Constitution = project law.
- AI Library = durable engineering memory.
- Architecture/ownership docs = design authority.
- Git = code and migration truth.
- Supabase production = runtime/data truth.
- Conversation context = temporary working memory only.

## Required session cycle

`READ -> AUDIT -> CLASSIFY -> REPAIR -> TEST -> VERIFY -> DOCUMENT -> GREEN`

A material change is not complete until durable memory is updated when it changes architecture, ownership, security posture, release baseline, or teaches a reusable incident lesson.

Never overwrite historical evidence. Append decisions/releases; update CURRENT_STATE only to the latest evidence-backed state.
