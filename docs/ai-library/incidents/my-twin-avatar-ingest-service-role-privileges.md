# Incident — My Twin avatar ingest service-role privileges

## Status
RESOLVED

## Evidence
RUNTIME_VERIFIED — 2026-08-29

## Symptom
My Twin reached `Stap 3/3 · Beveiligde versie privé opslaan…` and the authenticated Edge Function returned `Image security service unavailable`.

## Root cause
`public.avatar_ingest_attempts` was intentionally denied to client roles, but the hardening also left `service_role` without the `SELECT`, `INSERT` and `DELETE` table privileges required by `my-twin-image-ingest`. The related identity sequence also required service-role usage.

The table's `id` column was verified as `GENERATED BY DEFAULT AS IDENTITY`; no identity/default repair was required.

## Repair
- Restore `SELECT`, `INSERT`, `DELETE` on `public.avatar_ingest_attempts` to `service_role`.
- Restore `USAGE`, `SELECT` on `public.avatar_ingest_attempts_id_seq` to `service_role`.
- Keep `anon` and `authenticated` fully revoked from both table and sequence.

## Prevention
When hardening a server-only table, verify both sides of the contract:
1. client roles have no direct access;
2. the backend execution role retains the minimum privileges needed by the canonical Edge Function.

RLS bypass does not replace PostgreSQL object privileges.
